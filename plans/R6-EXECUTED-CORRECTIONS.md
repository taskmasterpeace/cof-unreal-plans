# R6: The plans corrected from executed results

Written 2026-11-13 for ledger job J84. No Unreal used. Nothing committed by this job.

## 1. What this is

The plans (01 to 17) were first written by reading the browser game's code. Three later jobs ran the game's real code
with fixed inputs and saved what it did: movement and knock-back (job J10, `Data/cases/`), powers and damage (job J11,
`Data/cases/power_*.json` and `Data/cases/damage_*.json`) and the world (job J12, `Data/golden/`). Each of those jobs
listed where a plan was wrong. Two more jobs measured other things: job J07 froze what the Unreal slice's knock-backs
really do (`Data/frozen-knockbacks.json`) and job J13 wrote the course's sizes into `Data/course-stations.json`.

An executed result outranks a reading of the code. This job opened each named result file, read the values, and
corrected the plan lines in place. This note lists every correction, with the data file and the key inside it that
each number comes from. A script, `docs/proof/J84-check-r6.py`, re-opens every one of those files and confirms the
number is there.

**Slice numbers were not turned into browser-game numbers.** Where the Unreal slice and the browser game differ, the
plan now gives both and names each. Section 5 lists those places.

## 3. Every correction

How to read the tables:

- **Where** is the plan file and the line in the file as it is now, then the line it was on before this job.
- **Old text** and **New text** give the words that matter. Where a whole passage or table was replaced, they say what
  it said and what it says now, not every word.
- **From** is the finding that asked for the change: the row of the table in the proof of job J10, J11 or J12, or the
  proof of J07 or J13.
- **Check** is what the script looks up. `file :: key` = **number** (2 dp) means: the value at that key in that file,
  rounded to 2 decimal places, is that number. A line starting "calc" works a number out from values in the files
  (a ratio or a difference). Keys: `cases[some-id]` is the case with that id; `rows[0]` is the first row;
  `rows[stepsLate=6]` is the row whose stepsLate is 6; `#len` is a count.

## 8. How to check this note

`python docs/proof/J84-check-r6.py` reads the tables in section 3. For every row it opens each named data file, finds
the key, and compares the value with the number quoted, rounded as the row says. It prints PASS or FAIL per row and
ends with a non-zero exit code if any row fails. The saved output is `docs/proof/J84-check.txt`; the proof that it can
fail is in `docs/proof/J84.md`.

Since critic fix 6 (2026-11-13) the checker also opens the plan file each row cites and requires every number of the
row's new text to stand on the cited line, or within 3 lines of it; a row whose correction spans a paragraph and its
table cites a line range ("lines 132-147"). Rows 15, 37 and 38 quote the knock-back numbers job J07 measured. Job J82
re-froze `Data/frozen-knockbacks.json` afterwards with different numbers, so those rows are now checked against J07's
table, kept byte for byte in `Data/history/frozen-knockbacks-J07.json`. The plans' knock-back tables (Plan 5 line 30,
Plan 8 lines 132-147 and 180-184) are J07's figures, not the slice's current ones, until J82 brings them up to date.

What the check does not prove: that the plan's sentence around a number is right, that the result files themselves are
right (jobs J10, J11 and J12 answer for those, and no critic has read them), or that every wrong plan line was found.
